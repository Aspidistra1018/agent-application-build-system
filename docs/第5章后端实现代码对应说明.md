## 5. 第 5 章综合创新在代码中的体现

第 5 章的综合创新点可以概括为：

1. 用画布节点和边描述多智能体任务图。
2. 用统一状态对象、Checkpoint、执行历史保存工作流运行状态。
3. 用 Prompt 模板、对话历史、知识库召回增强中文场景效果。
4. 用 ReAct Agent 支持模型自主选择插件或子工作流工具。
5. 用 Batch、RAG 并行检索、异步流式执行降低时延。
6. 用耗时、Token、执行状态记录支持后续分析和优化。

## 6. 答辩速记版

可以按下面顺序讲：

1. **任务规划**：前端画布配置节点和连线，后端通过 `CanvasToWorkflowSchema` 转成工作流 Schema，再由 Eino 编译为 DAG。
2. **状态管理**：运行时 `State` 保存节点上下文、中间结果、恢复数据和嵌套工作流状态，Checkpoint 用 Redis 持久化。
3. **Prompt 与记忆**：LLM 节点把系统 Prompt、用户 Prompt、变量、历史消息和知识库召回内容组合成模型输入。
4. **工具调用**：如果 LLM 节点配置了插件或工作流工具，就创建 ReAct Agent，让模型自主决定工具调用。
5. **并行优化**：Batch 节点并发执行数组任务，知识库检索并行执行向量、全文和 NL2SQL，整体工作流支持异步和流式返回。
6. **指标闭环**：每次执行记录节点耗时、总耗时、Token 使用和错误状态，为后续优化提供依据。

## 7. 容易被问到的问题

**问题：第 5.3 写了关键路径法，代码里有没有单独实现 CPM？**

回答：

> 目前代码里没有单独命名为 CPM 的实现，也没有显式计算 ES、EF、LS、LF 和 Slack。论文中的公式用于说明调度目标。工程实现中依赖 Eino DAG 引擎完成拓扑依赖调度，系统自己负责把画布转换成节点依赖图，并在 Batch、RAG 检索、异步执行等位置实现并行优化。

**问题：长期记忆在哪里体现？**

回答：

> 短期记忆是 ChatFlow 的历史消息，按轮数注入 Prompt；长期记忆是知识库检索，代码中通过 `Retrieve` 同时做向量检索、全文检索和 NL2SQL 检索，再把召回片段插入 Prompt。

**问题：多智能体怎么体现？**

回答：

> 每个 LLM 节点、插件节点、子工作流节点都可以看作一个具备独立能力的任务单元。LLM 节点还可以通过 ReAct 调用插件或其他工作流，把多个能力节点组合成一个可执行流程。
