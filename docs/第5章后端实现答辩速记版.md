# 第 5 章后端实现答辩速记版

这份只记答辩必须讲清楚的内容：**前端不是直接执行 `CanvasToWorkflowSchema`，前端调用运行接口后，先进入工作流执行服务，再由执行服务调用画布转换函数。**

## 1. 一句话总流程

```text
前端点击运行/调试
  -> 后端 ApplicationService.TestRun
  -> Workflow Domain Service.AsyncExecute
  -> 读取数据库里的 workflow.Canvas
  -> CanvasToWorkflowSchema 转成 WorkflowSchema
  -> compose.NewWorkflow 编译成可执行 DAG
  -> AsyncRun / StreamExecute 执行
```

## 3. `CanvasToWorkflowSchema` 在哪里

定义位置：

```text
backend/domain/workflow/internal/canvas/adaptor/to_schema.go:66
```

核心作用：

```text

  -> WorkflowSchema.Nodes
  -> WorkflowSchema.Connections
  -> WorkflowSchema.Branches
  -> sc.Init()
```

关键代码位置：

| 代码位置 | 作用 |
|---|---|
| `to_schema.go:73` | 去掉孤立节点，只保留有效连接的节点和边 |
| `to_schema.go:81` | 建立 `nodeMap`，后面处理连线端口时要用 |
| `to_schema.go:114` | 调用 `NodeToNodeSchema`，把画布节点转成后端节点 Schema |
| `to_schema.go:119` | 加入 `sc.Nodes` |
| `to_schema.go:130` | 把节点内部边转成 `Connection` |
| `to_schema.go:135` | 把画布外层边转成 `Connection` |
| `to_schema.go:139` | 规范化端口，比如选择器分支端口 |
| `to_schema.go:145` | 根据连接关系生成分支信息 |
| `to_schema.go:152` | 初始化最终 `WorkflowSchema` |

答辩说法：

> `CanvasToWorkflowSchema` 是画布适配层，不负责真正执行。它把前端画布里的节点、边、分支、子流程关系转换成后端统一的 `WorkflowSchema`，后续再交给 Eino 编译执行。

## 4. 前端到底先执行哪个

前端不直接执行 Go 函数。正确顺序是：

```text
先进入 executable_impl.go 里的执行函数
再由执行函数调用 CanvasToWorkflowSchema
```

答辩说法：

> 前端点击运行后，只是发起接口请求。后端先进入 `AsyncExecute` 等执行函数，执行函数读取工作流画布数据，然后调用 `CanvasToWorkflowSchema` 完成转换。

## 6. 最容易被问的问题

**问：`CanvasToWorkflowSchema` 是执行工作流的吗？**

答：

> 不是。它只负责把前端画布转换成后端 `WorkflowSchema`。真正执行是在 `AsyncExecute` 中创建 `compose.NewWorkflow` 后完成的。

**问：前端先执行 `CanvasToWorkflowSchema` 还是执行服务？**

答：

> 前端不直接执行 Go 函数。前端先调接口，后端进入 `AsyncExecute`，然后 `AsyncExecute` 内部再调用 `CanvasToWorkflowSchema`。

**问：第 5.3 的关键路径算法代码在哪里？**

答：

> 代码里没有单独命名为 `CriticalPath` 或 `CPM` 的函数。论文公式用于说明优化目标，工程实现主要依赖 Eino DAG 调度和 Batch、RAG 的并行执行机制。

## 7. 30 秒背诵版

> 前端点击运行后，会进入后端工作流执行服务，比如 `AsyncExecute`。执行服务先读取数据库中的画布 JSON，反序列化成 `vo.Canvas`，再调用 `CanvasToWorkflowSchema` 转成 `WorkflowSchema`。这个 Schema 包含节点、连线和分支关系，之后通过 `compose.NewWorkflow` 编译成 Eino 的 DAG 工作流并执行。第 5 章里的任务规划对应这个 DAG 转换和执行过程；中文 Prompt 与记忆对应 LLM 节点的 Prompt 渲染、历史消息和知识库检索；并行优化对应 Batch 节点并发、RAG 并行检索和异步流式执行。
